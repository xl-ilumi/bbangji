# 🗄️ 데이터베이스 스키마 설계 및 구축 가이드

## 1. 개요

Supabase의 PostgreSQL을 사용하여 프로젝트에 필요한 테이블을 설계하고, 보안 정책(RLS)을 설정하는 단계입니다.

## 2. 테이블 설계 (ERD)

### 2.1. 사용자 프로필 테이블 (`profiles`)

Supabase의 `auth.users` 테이블은 직접 수정할 수 없으므로, 사용자 정보를 담을 별도의 `public` 테이블이 필요합니다.

- **id**: UUID (Primary Key, Foreign Key -> `auth.users.id`)
- **email**: Text (읽기 전용, `auth.users`와 동기화)
- **username**: Text (닉네임)
- **avatar_url**: Text (프로필 이미지 경로)
- **updated_at**: Timestamp with time zone

### 2.2. 데이터 테이블 예시 (`notes`)

사용자가 작성할 데이터를 저장하는 테이블입니다. (프로젝트 성격에 따라 `todos`, `posts` 등으로 변경하여 사용)

- **id**: BigInt (Primary Key, Identity)
- **user_id**: UUID (Foreign Key -> `profiles.id`)
- **title**: Text (제목)
- **content**: Text (내용, nullable)
- **is_complete**: Boolean (완료 여부, default: false)
- **created_at**: Timestamp with time zone (default: now())

## 3. 적용 단계 (Supabase SQL Editor)

Supabase 대시보드의 **SQL Editor**에서 아래 쿼리를 순서대로 실행하여 테이블을 생성합니다.

### 3.1. 테이블 생성 SQL

```sql
-- Profiles 테이블 생성
create table public.profiles (
  id uuid not null references auth.users on delete cascade,
  email text,
  username text,
  avatar_url text,
  updated_at timestamp with time zone,

  primary key (id),
  unique(username),
  constraint username_length check (char_length(username) >= 3)
);

-- Notes 테이블 생성
create table public.notes (
  id bigint generated by default as identity primary key,
  user_id uuid references public.profiles(id) not null,
  title text not null,
  content text,
  is_complete boolean default false,
  created_at timestamp with time zone default timezone('utc'::text, now()) not null
);
```

### 3.2. RLS (Row Level Security) 설정

데이터 보안을 위해 RLS를 활성화하고 정책을 추가합니다. **이 과정이 없으면 데이터가 조회되지 않거나 보안에 취약해집니다.**

```sql
-- 1. RLS 활성화
alter table public.profiles enable row level security;
alter table public.notes enable row level security;

-- 2. Profiles 정책: 프로필은 누구나 조회 가능, 수정은 본인만 가능
create policy "Public profiles are viewable by everyone."
  on profiles for select
  using ( true );

create policy "Users can insert their own profile."
  on profiles for insert
  with check ( auth.uid() = id );

create policy "Users can update own profile."
  on profiles for update
  using ( auth.uid() = id );

-- 3. Notes 정책: 오직 본인만 CRUD(생성/조회/수정/삭제) 가능
create policy "Individuals can view their own notes."
  on notes for select
  using ( auth.uid() = user_id );

create policy "Individuals can create notes."
  on notes for insert
  with check ( auth.uid() = user_id );

create policy "Individuals can update their own notes."
  on notes for update
  using ( auth.uid() = user_id );

create policy "Individuals can delete their own notes."
  on notes for delete
  using ( auth.uid() = user_id );
```

## 4. 타입 생성 (TypeScript 사용 시)

테이블 및 RLS 설정이 완료되면, 로컬 프로젝트에서 타입을 추출하여 동기화합니다.
**CLI 로그인과 저장 폴더 생성이 먼저 진행되어야 합니다.**

### 4.1. CLI 로그인

Supabase CLI를 사용하기 위해 먼저 로그인을 진행합니다. (최초 1회)

```bash
npx supabase login
```

### 4.2. 폴더 생성

저장할 경로(`src/types`)가 없으면 파일이 생성되지 않거나 비어있을 수 있습니다.

```bash
mkdir -p src/types
```

### 4.3. 타입 생성 명령어

아래 명령어를 실행하여 타입을 추출합니다. (프로젝트 ID: `wcyoeixzjcnwbeplndgu`)

```bash
npx supabase gen types typescript --project-id "wcyoeixzjcnwbeplndgu" > src/types/supabase.ts
```
